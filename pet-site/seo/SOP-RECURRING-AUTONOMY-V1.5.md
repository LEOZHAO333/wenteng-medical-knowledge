# 日宠通 GEO/SEO 标准执行流程 SOP V1.5
版本：2026-10-18 · 状态：**Founder已确认日常执行授权**；此文档存于 PR #8 Draft 分支，尚未合并主分支。

> **总原则：重复性、可逆、已定标准且不触及正式发布或对外承诺的工作，GPT无需逐次询问Founder，直接执行并留下可追踪记录。涉及重大决策才交Founder裁决。** 任何机器检查、编辑审核、Founder批准均不能取代执业兽医医学审核。

## 1. 角色与审批权

| 角色 | 职责与权限 | 禁止越权 |
|---|---|---|
| Founder | 品牌方向、业务模式、对外发布和索引、法律合规风险接受、预算/合同、权限与对外承诺等最终决策 | 不能替代真实执业兽医独立医学审稿 |
| GPT（常规执行负责人） | 按固定 SOP 连续选题、查重、资料整理、逐条验证证据、编辑草稿、建立台账、修正安全编辑问题、提交/更新 Draft PR、运行测试和复查错误 | 不自行合并主分支、部署、开放索引、发布平台内容、签署合同、扩大权限、标记Medical Approved |
| GitHub Actions（只读检查器） | PR更新后自动核对ID/Slug、来源审核格式、重复、风险队列、内容授权闸门、测试与历史错误防回归 | 不写入线上、不自动审批医疗事实、不自动 merge/push/部署 |
| 真实执业兽医 | 高风险医学断言、诊疗边界、处方药/疾病等专业审核与独立署名 | 不由模型、自称专家或自动QA冒充 |

## 2. 直接自动执行：无需每次确认（A0）

触发：“继续”“按标准推进”、常规内容队列或代码PR更新。仅在 **Draft分支** 和已批准范围内开展；不需要逐批请示。

1. **收集/排序**：从现有579→582等真实主库读取ID/标题、S/A优先级、来源批次和审核状态。新增高频问题先查重、定唯一ID候选，不未经查证建立公开URL。
2. **选题/GEO**：关键词意图分层、猫狗疾病专题聚类、问答短答（50–100字）、科普文章（按现行450–500字四段）、SEO标题建议、适用对象/风险边界、相关ID建议。
3. **来源校对**：逐题比对原始正文和可信官方/学协会/教材来源，记录可打开链接、机构、核对日期与**每个链接支持的断言**；存疑则标 pending/hold，不为了补数量硬填verified。
4. **编辑级修订**：错别字、格式、链接去追踪参数、清晰免责声明、紧急风险优先、已确定的引用过度归因改正；保留原文差异和历史版本。
5. **内容入库**：仅向现有 pet-site/content 主库/对应审稿台账添写草稿，保留原始ID、Slug和历史，不删除/替换旧上线页面；重复题先标记候选，不能无证据合并不同临床意图。
6. **技术质量**：局部非生产变更，例如审核脚本、测试、规则文档、静态索引策略纯函数、CI只读检查；在现有Draft分支提交并跑CI。可单独新建**Draft技术PR**，但不合并、不部署。
7. **审计报告**：按批次输出完成ID、来源范围、P0/P1/P2、编辑层修复、医学待审、结构化QA、待办与下一批；只将“重大待决事项”集中上报Founder。
8. **重复任务接续**：有后续批次时直接按队列执行，不再提出“是否继续”“是否可以整理”“是否允许编辑草稿”等重复确认。

> A0的“自动”指在**可用的当前交互或已连接且预先启用的触发器**内执行。GitHub PR Actions可在符合触发条件时自动运行只读测试，但不会因此让GPT在无人发起对话时无限期持续工作；不宣称具备尚未设置的定时无人值守内容生成能力。

## 3. 遇到条件自动继续或自动阻断（A1）

- P2：文字、标题/关键词、格式、来源说明与安全文案的小问题 → GPT可直接改稿、追加回归检查，并记录更改理由。
- P1：缺关键证据、来源断链、Slug冲突、疑似重复题、难以区分疾病或研究状态 → GPT先搜证/核对/修正；不能自证时标记**Hold**，继续处理下一条，不中断整个队列。
- P0：可能错误诊疗/急症提示、犬猫物种或用药批准状态、虚构来源或隐私泄露 → **立即阻断受影响条目**，清除未经证实断言并留痕。若风险可在既定编辑标准内修复，GPT先修草稿再走兽医复核；不能独立确认的重大临床/法务问题集中报Founder，不以错误内容推进。
- CI失败：定位到文件、修复、重跑；未通过不可宣称PASS。若存在无法解释的安全/权限冲突，则暂停相关写入并明确报告。
- 用户后续明确修改本SOP的某项规则，则按最新明确授权变更，不利用旧授权抵触用户新要求。

## 4. 必须 Founder 明确确认的重大事项（B0）

**决策需要明确的“同意/批准＋对象＋范围”，不能根据沉默或“继续”推定。**

- **品牌/战略**：日宠通定位、名称、Logo、首页或信息架构重大调整、独立域名、目标市场、商业模式、收费/销售/咨询入口及转化路径。
- **上线/公开**：合并到`main`、生产部署、公开网站、解除`noindex`、修改robots/Crawl政策、申请/提交可索引Sitemap，以及向公众号/百家号/Facebook等平台实际发布（除非将来另有明确逐平台发布授权）。
- **网站与数据风险**：批量301/删除/迁移永久URL、批量替换既有线上正文、超出既定范围的结构性代码、删除项目文件、外部账号权限、连接新第三方、访问控制、敏感数据处理。
- **商业/法律**：预算支出、签约付款、对外合作承诺、日本药械监管/跨境医疗政策判断、广告/合规免责和风险承担等。
- **医学权威**：执业兽医医学签署；日本具体动物用医药品的批准与适应症按MAFF/NVAL产品级核对。即使Founder批准发布，也**不可自动将内容标为Medical Approved**，审稿权属于合资格兽医。
- **高影响不确定性**：新医疗功效、独立给药建议、无法核实的药品批准、产生实际患者/宠物风险的医疗或伦理原则变动。

## 5. 两种处理流程

**日常线：**
`取下一批待办 → 先去重 → 权威来源核对 → 编辑修订 → 记录ID/Slug/证据/风险 → 更新Draft与台账 → CI→ (PASS则接续下一批，FAIL则修复) → 汇总`

**重大决策线：**
`发现B0 → 暂停该决定关联的写操作与受影响条目 → 列出背景/2个可选方案/风险/推荐/明确需批准的动作 → 一次性请Founder裁决 → 将批准凭据与范围记录到PR/Issue → 在批准范围内执行→复核`

未被B0阻塞的其他普通任务可以继续。不要重复询问已获明确回答的同一个决定；只有范围、风险或环境出现实质变化时才再次请示。

## 6. 每次执行的固定交付格式

- **版本/批次/PR及commit**：例如 V1.5、Batch 13、PR #8；
- **事实台账**：正文总数、编辑核验记录、未核验数、真实兽医Medical Approved数（未获得即0或unknown）、已发布数（未上线即0/未验证）；
- **本批结果**：ID、原问题、原稿、支持来源、已更改、待医学审核/P0/P1；
- **QA**：GitHub Actions链接、HEAD SHA、真实success/failure，不用旧run冒充新提交；
- **重大待裁决**：仅列B0；没有写“无重大事项，不需要你操作”；
- **下一步**：继续队列无需用户再次回复“继续”。
